## 论文核对（两项悬置问题的结论）

**B4 + RS 自生收缩。** 审计中一度怀疑 `epsilonAuCem(RS) = −84×10⁻⁶` 漏了符号：由于模型公式自带前导负号（`ε_au∞ = −ε_au,cem (a/c/6)^{r_εa} (w/c/0.38)^{r_εw}`），RS 水泥的自生项恒为正（膨胀），而 B4s 对同一混凝土恒为收缩。核对两份**独立复现论文参数表**的来源后确认这是论文原值：

- 一份逐表复现 RILEM 表的学位论文（IIT Madras，Tables 2.1–2.6）：`ε_au,cem = 210 / −84 / 0 ×10⁻⁶`（R/RS/SL），`τ_au,cem = 1 / 41 / 1`，公式同带前导负号；
- 一份照论文写的独立实现（TC-242-MDC，K. Zdanowicz，DOI 10.1617/s11527-014-0485-2）：`eps_au_cem = -84e-6`。

因此 RS 膨胀、SL 恒为 0 是模型构造，不是缺陷；两份来源同时逐位验证了内核其余表格（收缩水泥表、24 行收缩外加剂表、骨料表、形状系数、B4s 两张表，以及 `k_h` 在 0.98 处的切换）。R 路径另有论文 §1.9 基准（−36.97 µε）钉住。新增测试把三类的已发表数值固定下来，避免日后被"顺手修正"。

（顺带发现：该独立实现的自生项用 `(t̃ − t̃₀)`，与推荐做法和本内核的 `(t̃ + t̃₀)` 不同；§1.9 基准只有加号能复现，故按论文的是本内核。）

**MC2010 基准的 `/1.05`。** 原测试里有一条无法解释的除数：`φ/1.05 ≈ 1.563`。SOFiSTiK 2025 验证手册 DCE-MC1 §38.4（p. 320）写明：

> The total creep coefficient: ϕ(t,t₀) = 1.385 + 0.2587 = **1.64**
> According to Model Code 2010, the creep value is related to the tangent Young's modulus E_c, where E_c being defined as **1.05 · E_cm**. To account for this, SOFiSTiK adopts this scaling for the computed creep coefficient… ϕ(t,t₀) = 1.64 / 1.05 = 1.56

即手册自己的模型总值就是 1.64（与内核的 1.6452 及各分量一致），`/1.05` 是把 φ 换算到切线模量基准的**报告口径**。fib 官方实现（`structuralcodes` 的 MC2010 模块）逐条与本内核相同且全篇没有该因子，所以它留在测试里作为口径说明，**不进内核**。测试现在把它命名为 `TANGENT_MODULUS_RATIO`，并分别断言模型总值与参考基准。

## 语言标记清扫（N-18）

界面是中英混排而文档是 `<html lang="en">`，中文片段此前没有自己的 `lang`，屏幕阅读器会用英语音素朗读。清扫分两类处理：

- **静态 JSX** 就地包 `<span lang="zh-CN">`，标记写在写它的地方；
- **数据来的字符串**（问题信息、告警标题与正文、参数中文说明、分组标签、超限提示、截断提示、阶段标签）经 `<Lang>` 组件按字符类切分，中文段自动带上 `lang="zh-CN"`。切分按字符类而非分隔符，因为字符串有 `File is empty. 请上传…`、`Required column is missing · 缺少必填列`、`上传数据` 三种形态；**文本内容逐字符不变**，所以读屏、复制与既有断言都不受影响。

守护测试 `src/components/languageMarkup.test.jsx` 走查真实 DOM：任何含汉字的文本节点，以及任何含汉字的 `aria-label`/`title`/`placeholder`/`alt`，都必须落在带 `lang="zh…"` 的元素内；覆盖单点工作区（含超限与"结果待更新"两种状态）、告警、批量工作区（映射面板、问题表、空文件错误、150 行截断提示与可视化说明）、参考库、命令面板，以及 MC2010 的跨字段提示。另外三条测试钉住切分本身：形态覆盖、拼接后与原串逐字符相同、被标记的片段确实含汉字。

不在范围内：`index.html` 的 `meta description`/`keywords`（不进入阅读流）与 `public/模型说明/*.md`（下载文档，非 DOM）。

## 方法

- 每条缺陷先用**临时 vitest 用例**在真实代码上复现并记录实测值（例如 `phi@35 = 1.470112` 对 `phi@90 = 0.980565`、`location.search = ""` 对 `state.mode = "batch"`、`b4Single(h:'') === b4Single(h:0)`），修完用同一复现复验；临时文件已删除。
- 内核侧另有两条独立证据链：JS↔Rust 源码/预编译 wasm 的数值对拍（152,326 + 724,370 次字段比较，最大相对差 ~3e-16，并确认预编译 wasm 与 `rust-engine/src` 同步），以及四模型有效域内的 fuzz（无 NaN/Infinity 泄漏，唯一例外即 N-2）。
- 四个修复提交各自在独立 git worktree 中跑过完整测试，提交信息末尾的测试数即该树的实测值（208 → 218 → 223 → 230）；本轮语言清扫后为 241。
